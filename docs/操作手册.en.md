# Mock Server User Guide

> Task-oriented quick reference for daily use (joint debugging / testing). For architecture and the full rule-syntax reference, see [README.md](../README.md) and [README.en.md](../README.en.md).
> Project path: `mock-server/` (zero dependencies, needs Node ≥ 16).


---

## 1. Quick start (3 minutes on your machine) <!-- sec:man-01 -->

```bash
cd mock-server
node server.js                      # passwordless mode, default port 18080
# or account+password mode:
MOCK_ADMIN_USER=admin MOCK_ADMIN_PASS=admin123 PORT=18082 node server.js
```

| Address                                    | Purpose                                                        |
| ------------------------------------------ | -------------------------------------------------------------- |
| `http://127.0.0.1:18080/`                  | Console (three-pane)                                           |
| `http://127.0.0.1:18080/{module}/{api}`    | Mock call entry (the upstream URL you point the system-under-test at) |

The three panes: **left** = API list → **middle** = rule editor → **right** = live request log. Save a rule and it takes effect immediately — no restart.

## 2. Deploy-mode cheat sheet <!-- sec:man-02 -->

| Mode                         | How to start                               | Who can open the console            | Can generate share links                                          |
| ---------------------------- | ------------------------------------------ | ----------------------------------- | ----------------------------------------------------------------- |
| Passwordless                 | `node server.js`                           | Anyone                              | ❌ (403, unless `READONLY_PORT` is set)                           |
| Passwordless + read-only port | `READONLY_PORT=18081 node server.js`      | Anyone                              | ✅ share links land on the read-only port; stripping `?share=` gets you nothing — no config at all |
| Account+password             | `MOCK_ADMIN_PASS=secret node server.js`    | Login required (default user `admin`) | ✅ after login; link points at the main port                      |
| Account+password + read-only port | set both                              | Login required                      | ✅ (link still uses the main port)                                |

**Environment variables at a glance** (all optional):

| Variable                                          | Default | Notes                                                            |
| ------------------------------------------------- | ------- | ---------------------------------------------------------------- |
| `PORT` / `config.server.port`                     | `18080` | Main port                                                        |
| `MOCK_ADMIN_USER`                                 | `admin` | Deploy admin username                                            |
| `MOCK_ADMIN_PASS`                                 | empty   | Set it to enable login protection                                |
| `READONLY_PORT` / `config.server.readonlyPort`    | `0` (off) | Isolated read-only port, dedicated to share links              |
| `MOCK_DEFAULT_LANG` / `config.defaultLang`       | Chinese | Default deploy language (overridden by the user's own choice)    |
| `MOCK_SEED`                                       | —       | Set `1` to seed demo logs                                        |

> ⚠️ The variable is `MOCK_ADMIN_PASS`; writing `ADMIN_PASSWORD` does nothing (it silently falls back to passwordless).
> The startup banner prints the current login mode: `Console login : enabled/disabled` — no need to guess.

### Deploy to a test server (one-click script) <!-- sec:man-02b -->

Run locally (`deploy.sh` ssh-es over, installs, enables on-boot, and opens the port):

```bash
cd mock-server
./deploy.sh root@<test-server-IP> -r 18081   # passwordless + read-only port 18081 (recommended for testers)
```

| Result                          | Address                                                                                  |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| Edit rules yourself             | `http://<test-server-IP>:18080/` (passwordless — anyone can edit, don't expose it)       |
| Read-only link for testers      | generated from the share icon (top-right); looks like `http://<test-server-IP>:18081/?share=shr-xxxx` |

- On the read-only port: `/login` is disabled and all writes return 403; **every endpoint except `/_admin/auth` requires a valid share link** — calling `/_admin/config`, `/_admin/share` etc. without a token returns 403 (blocked by the server), while the page shows "a valid share link is required". Stripping `?share=` from the URL lands on that prompt page.
- The firewall must open **both** ports (the script opens them via firewalld); **keep the main port open only to you / the internal network** — don't expose `18080` publicly.
- Container mode (host has no node): `./deploy.sh root@<test-server-IP> -m docker -r 18081`.
- The read-only port must differ from the main port; `-r` is equivalent to the `READONLY_PORT` env var.
- **Updating an already-deployed instance**: use the identical arguments and re-run the same command (idempotent; the remote `config.json` is preserved, rules are kept) — see README 4.6.
- The top-bar "Contact maintainer" (✉) and "GitHub" come from the remote `config.json` `meta`: the former reads `contactEmail`, the latter reads `repoUrl` (set the email only on the target machine, don't commit it; the repo URL is public info).

```bash
ssh <user>@<HOST_IP> 'cd <install-dir> && node -e "const fs=require(\"fs\"),c=JSON.parse(fs.readFileSync(\"config.json\",\"utf8\"));c.meta=Object.assign({contactLabel:\"维护者\"},c.meta,{contactEmail:\"you@example.com\"});fs.writeFileSync(\"config.json\",JSON.stringify(c,null,2));console.log(c.meta)"'
```

## 3. APIs and rules (your daily main operation) <!-- sec:man-03 -->

1. Left panel **☰ → New group / New API**; the API path = `/{module}/{api}` (e.g. `/demo/sample`).
2. Middle panel **+ New rule** to add a rule; each rule = match condition + response:
   - **Value source**: request body / URL param / request header / raw text;
   - **Operator**: contains, prefix, regex, belongs-to, exists, numeric compare, etc.;
   - Array wildcards supported (`items[*].code`); multiple rules match **top-down, stop at first hit**; drag to reorder;
   - A rule can be disabled/enabled (toggle) or duplicated (copy this rule).
3. **Fallback response**: what to return when no rule matches — required.
4. **Proxy to upstream**: set the real service root URL in API settings; when the API doesn't hit a mock behavior it passes through to the real upstream — good for "mostly real, a few mocks".
5. **Scripted response**: choose the script response type to generate different returns per request item (syntax in README chapter 7).

Top-right of the middle panel **Try a shot**: fill the request body → send → see directly which rule matched and what it returned. Try a shot before joint debugging to tell "rule misconfigured" apart from "system-under-test called wrong".

## 5. Point the system-under-test at the mock <!-- sec:man-05 -->

- Change the system-under-test's upstream base URL to `http://<mock-server-IP>:18080` (**no trailing `/`**).
- The top-bar 🔗 icon copies the full call URL (base + current API path).
- Local debug example: `http://127.0.0.1:18080/demo`.

## 6. Share links (read-only view, for colleagues to see rules) <!-- sec:man-06 -->

Top-bar **share icon** → in the dialog **generate share link**:

- Each link has a **copy icon** on the left (hover shows "copy link"); click to copy; on the right **revoke** invalidates it anytime.
- The recipient can only view rules, not edit; the server also rejects writes as a backstop.
- In passwordless + read-only-port mode, links land on the read-only port — **even if the recipient strips `?share=` from the URL it stays read-only**, never reaching the editable main port.
- When a link expires (revoked), the recipient sees a "share link expired" page, never downgraded to an editable view.

| Fact          | Notes                                                                  |
| ------------- | ---------------------------------------------------------------------- |
| Token storage | `config.json` `shareTokens`, max 20                                    |
| Token passing | `Authorization: Bearer <token>` or URL `?share=<token>`                |
| Revoke        | in the dialog, or `DELETE /_admin/share?token=<token>`                |

## 7. Login and user management <!-- sec:man-07 -->

- **Deploy admin**: `MOCK_ADMIN_USER` / `MOCK_ADMIN_PASS` env vars, highest priority, can manage normal users.
- **Normal users**: stored in `config.json` `users` (SHA-256 hash, no plaintext). After login, click the avatar → **Users** to add/remove/edit.
- Both account types can coexist; read-only share links need no login.
- Forgot the deploy password: restart with a new `MOCK_ADMIN_PASS`; to change a normal user's password use the UI, or `tools/add-user.js <user> <password>`.

## 8. Request-log troubleshooting <!-- sec:man-08 -->

The right panel scrolls live for each matched request: time, path, status code, latency, matched rule.

| Action                  | Entry                                                          |
| ----------------------- | ------------------------------------------------------------- |
| Current API only        | first toggle in the right panel                               |
| Pause auto-refresh      | second toggle in the right panel                              |
| Clear                   | Clear (clears all logs; hit counts unaffected)                |
| Filter history by API   | `GET /_admin/logs?apiId=<id>&limit=50`                       |

> The log keeps a **copy** of each body, at most 100KB per entry: beyond that only the first 100KB is
> kept, the original size is stated at the end, and the drawer says the body is partial — do not read
> a partial body from the log as if it were whole. **The system under test always receives the
> complete body**; truncation only affects the log. Tune with `MOCK_LOG_BODY_LIMIT` (bytes).

## 9. Import / export and migration <!-- sec:man-09 -->

- **Export**: top-bar "Export" yields JSON (APIs, groups, rules).
- **Import**: top-bar "Import"; on conflict choose: skip / overwrite local / import as a renamed copy (good for diffing two configs).
- **Whole-machine migration**: just copy the whole directory (`config.json` is the entire state); no export needed.

## 10. Server deploy and operations <!-- sec:man-10 -->

| Method          | Command                                                            | Notes                                  |
| --------------- | ----------------------------------------------------------------- | -------------------------------------- |
| One-click script | `MOCK_ADMIN_PASS=secret ./deploy.sh root@<HOST_IP>`              | package & upload + systemd/cron launch |
| systemd         | see `mock-server.service`, `Environment=MOCK_ADMIN_PASS=...`      | recommended, auto-start on boot        |
| Docker          | `MOCK_ADMIN_PASS=... MOCK_PORT=18080 ./deploy.sh` (compose mode) | see `docker-compose.yml`               |
| Bare process    | `nohup node server.js &` + `@reboot` cron                         | deploy.sh default fallback             |

Ops notes:

- Logs: `mock-server.log` (script-launched) or `journalctl -u mock-server` (systemd).
- Firewall: **open the read-only port, lock down the main port** for full isolation (otherwise the share isolation is meaningless).
- After editing `config.json`: Reload config in the UI, or `POST /_admin/reload`; the server also watches the file and auto-reloads (including users).
- Health check: `GET /_admin/health`.

## 11. FAQ <!-- sec:man-11 -->

| Symptom                                  | Cause & fix                                                                                     |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Set env var but still passwordless       | wrong var name (should be `MOCK_ADMIN_PASS`); check the startup banner                         |
| Edited a rule but the UI didn't change   | browser cache — hard-refresh with `Cmd+Shift+R`                                                 |
| Recipient can't open the share link      | read-only port not opened in firewall; or link was revoked                                      |
| Share button 403 in passwordless mode    | expected protection: passwordless mode won't generate shares unless `READONLY_PORT` is set     |
| Port already in use                      | `lsof -nP -iTCP:18080` to find the process; or change `PORT`                                    |
| Chinese UI shows English sample text     | stale frontend cache — hard-refresh; `seed.*` text now follows the UI language                 |
| Local `curl` to localhost gets 502       | env proxy hijack — add `--noproxy '*'`                                                          |
| Bad scripted response drags down server  | a single request's error is caught by the process fallback; the server won't crash; just fix the rule |

## Appendix B: Admin API quick reference <!-- sec:man-b -->

| Endpoint          | Method                | Notes                                          |
| ----------------- | --------------------- | ---------------------------------------------- |
| `/_admin/auth`    | GET                   | auth / read-only status (called at frontend startup) |
| `/_admin/login`   | POST                  | login, returns session token                   |
| `/_admin/share`   | GET / POST / DELETE   | share links list / generate / revoke (listing is for editable identities only; a share token or the read-only port gets 403) |
| `/_admin/users`   | GET / POST / DELETE   | user management (deploy admin only)            |
| `/_admin/logs`    | GET                   | history logs                                   |
| `/_admin/health`  | GET                   | health check                                   |
| `/_admin/reload`  | POST                  | re-read config.json                            |

> All admin endpoints require a session (login token or share token, in `Authorization: Bearer`).
